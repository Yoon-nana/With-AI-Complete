# 정선 AIGO · IN 서비스

**웹 시작 주소: https://yoon-nana.github.io/With-AI-Complete/**

## 현재 사용 방법

1. 프로젝트 전체를 다운로드하고 압축을 풉니다.
2. Windows에 Python 3.13을 설치한 뒤 `IN_Install.cmd`를 한 번 실행합니다. 프로젝트의 `.venv`에 필요한 패키지를 설치하고 HTML 시작용 연결 도우미를 등록합니다.
3. 웹 시작 주소 또는 `IN_Start.html`을 열어 서비스 화면을 시작합니다.
4. 공통 상단바에서 로보독과 마이크로비트의 실제 COM 포트를 각각 선택합니다. 포트 번호는 PC마다 다릅니다.
5. 마이크로비트 V2에는 「마이크로비트 프로그램 다운로드」로 받은 파일을 최초 1회 설치합니다. 실제 탐색기 이미지로 설치 과정을 안내합니다.

## 포함한 변경

- 단일 마이크로비트 펌웨어: A 무응답 감지 / B 체조 / A+B 휴식. 모델 전환 중 809 오류 원인을 수정했습니다.
- 체조 목표 횟수 달성 시 키오스크와 같은 랜덤 로보독 반응을 실행합니다.
- 무응답 감지 켜기·끄기와 순찰 시작 시간·쓰러짐 확인 후 모의 신고 대기 시간을 저장합니다.
- 무응답 감지를 끄면 마빗도 휴식 모드로 들어가 감지를 중단하고, 다시 켜면 감지 모드로 복귀합니다. 별도 프로그램 실행이나 재설치는 필요 없습니다.
- HTML에서 시작하고 장치는 상단바에서 연결합니다.
- 프로그램 다운로드와 함께 5단계 설치 안내를 표시합니다.

GitHub Pages는 정적 시작 화면입니다. Python과 USB 장치 제어는 각 PC의 로컬 연결 도우미가 담당합니다. 포트 설정·복약 예약·사용 기록은 PC에만 저장되며 저장소에 포함하지 않습니다. 실제 전화·문자 신고는 수행하지 않습니다.

# 로보독 도우미 · 키오스크 연습과 복약 알리미

## 최신 구성: 체조 · 낮잠 · 기본 안부 감시

실행은 main.py입니다. 로보독 COM4와 별도의 마빗 USB 포트(기본 COM6)를 사용합니다.

- 체조: 치어링·암컬·손목 돌리기 중 무작위 3~10회 목표가 나옵니다. 선택 동작의 마빗 카운트가 목표에 도달해야 다음 미션으로 넘어갑니다. 쉬기는 제외하며 시간만으로 완료 처리하지 않습니다.
- 낮잠: 낮잠 자기 → 몇 분 뒤에 깨워드릴까요? → 1~180분 입력 → 기존 알람에 자동 등록합니다. 낮잠 동안 무활동 위험 판단을 쉬고, 종료 시 알람을 끈 뒤 기본 감시로 돌아갑니다.
- 둘 다 아닌 때: Checking grandmother 모델의 ML,MOVING/STILL 신호로 기본 안부 감시를 합니다. 기존 로보독 얼굴 class1/2 판단과 모의 신고는 유지합니다.
- 학습 JSON 두 개는 models/에 원본 그대로 포함했습니다. 두 마빗 원본 코드는 microbit/checking_original.ts와 exercise_original.ts에 보존했습니다. runtime.ts는 원본 뒤에 통신·모드 연결만 추가했습니다.

### 아직 필요한 실제 모델 파일

이 배포본에는 학습 모델과 PC 통신 코드가 함께 들어 있는 models/checking.hex와 models/exercise.hex가 포함되어 있습니다. 두 HEX의 모델·클래스·실행 코드와 체크섬을 확인했습니다. 직접 코드를 붙여 넣거나 다시 학습할 필요는 없습니다. 실제 동작 인식 정확도와 기기 자동 전환은 마빗 V2에서 확인해야 합니다.
마빗 한 대의 자동 전환은 모델별 HEX를 MICROBIT 드라이브에 내려보내고 재연결하는 방식입니다. 파일이 없거나 모델 응답이 다르면 앱에 그 이유를 표시합니다. 준비 절차는 models/모델_준비_안내.md를 참고하세요.

실제 기기에서 모델 전환이나 인식 정확도는 아직 검증하지 못했습니다. 모의 카운트·시간·임시 MICROBIT 드라이브 및 기존 기능 테스트로 연결 코드를 검증합니다.

## 시작하기

ZIP을 풀고 robodog-helper-thonny 폴더 전체를 보관하세요. main.py만 옮기면 실행되지 않습니다.
기존 프로그램 창을 닫은 뒤 새 폴더의 main.py를 여세요.

작업 폴더 안에 .venv와 robodog-helper-thonny 폴더를 나란히 두는 구성을 권장합니다.
가상환경이 없다면 작업 폴더의 PowerShell에서 처음 한 번만 생성합니다.

```powershell
py -3 -m venv .venv
```

Thonny의 Tools → Options → Interpreter에서 PC용 Python/가상환경을 선택하고
작업 폴더의 .venv\Scripts\python.exe를 지정합니다. 메뉴 표기는 버전/언어에 따라 다를 수 있습니다.
PC Python에는 Tcl/Tk 지원이 있어야 합니다. 보드용 MicroPython에 업로드하는 프로그램이 아닙니다.

1. main.py를 열어 F5 또는 실행 버튼을 누릅니다.
2. 먼저 **모의 모드 → 기능 선택 열기**를 누릅니다.
3. 브라우저에서 **키오스크 연습 → 안내 버전 / 스스로 버전**을 고른 뒤 **1단계 아메리카노**를 선택합니다.
4. 연습 주문을 보고 매 스테이지에서 주문 전체 과정을 진행합니다.
5. **프로그램 종료** 또는 Python 실행 창의 종료 버튼으로 연결을 정리합니다.

브라우저가 자동으로 열리지 않으면 Thonny 셸에 출력된 전체 주소를 복사합니다.
HTML 파일을 직접 더블클릭하면 로봇과 연결되지 않습니다.
브라우저 탭만 닫아도 Python은 계속 실행됩니다. 실행 창의 **키오스크 다시 열기**로 돌아올 수 있습니다.
전체 화면 버튼이나 브라우저 F11을 사용할 수 있습니다.

## HTML 복약 알리미

1. 첫 화면에서 **복약 알리미**를 선택합니다.
2. 시·분과 **복용할 약 이름**을 입력하고 **복약 시간 추가**를 누릅니다. 최대 50개까지 추가할 수 있으며 목록에서 개별 삭제할 수 있습니다. 같은 시간의 서로 다른 약은 한 번의 알림에 함께 표시합니다.
3. 해당 시각에 약 이름이 크게 표시되고 로보독은 초롱초롱 눈 LED + 멍멍 소리 1회 → 기지개 → 서기 순서로 반응합니다. 기존 QR 인식 자세는 유지하고 각 몸동작 뒤 2초씩 기다립니다. 소리·몸동작 사용 여부는 시작 창 설정을 따릅니다.
4. 약을 드셨으면 화면의 QR을 인쇄하거나 다른 화면에 띄워 로보독 AI 카메라에 보여주세요. QR 내용은 **영문 대문자 STOP**입니다. 한글 ‘스탑’이나 소문자 stop은 확인으로 처리하지 않습니다.
5. STOP 확인 전까지 약 5초 간격으로 멍멍 소리를 반복하고 눈 LED와 QR 인식 자세를 유지합니다. 매번 sound()를 1회만 호출하고 4.5초 재생 여유를 둬 짖음이 겹치지 않게 합니다. 짖는 알림 중에는 PC 음성 안내를 하지 않습니다.
6. 소리 재생 대기 중에도 같은 워커에서 QR을 읽습니다. STOP을 받으면 다음 짖음을 금지하고 현재 소리 대기를 마친 뒤 **준비** 자세로 돌아가 2초 기다리고 눈 LED를 끕니다. 한국어 준비 상수를 우선 사용하고, 없는 버전은 STANDUP을 사용합니다. 다른 시각의 예약은 그대로 남습니다.

다른 시각의 알림까지 확인할 때는 이전 STOP QR을 한 번 내렸다 다시 보여주세요. 같은 QR을 계속 들고 있어 다음 예약이 자동 확인되는 것을 막습니다. 예약 전체 종료는 현재 알림과 남은 모든 예약을 함께 취소합니다. 이미 시작한 소리와 몸동작은 마친 뒤 멈추고, 뒤늦은 완료 처리나 재실행으로 취소한 예약을 다시 시작하지 않습니다. 예약·알림 중·완료·취소됨을 포함한 등록 항목을 목록과 저장 파일에서 모두 삭제하며 예약 개수는 0개가 됩니다.

각 예약은 **다음에 돌아오는 시각 한 번**입니다. 현재 분을 설정하면 바로 알림을 시작하고, 이미 지난 시간은 다음 날로 예약합니다. 매일 자동 반복하는 기능은 아닙니다. 완료 후 다시 예약할 수 있습니다. 여러 시각이 이미 지났다면 이른 시각부터 하나씩 확인하며 뒤의 예약을 함께 완료하지 않습니다.

PC와 Python 프로그램을 켜 두어야 하며 절전 중에는 정시에 실행되지 않습니다. 키오스크 화면으로 돌아가거나 브라우저 탭을 닫아도 Python이 실행 중이면 예약은 유지됩니다. 약 이름과 시간은 data/medication.json에 로컬 저장됩니다. 이전 단일 예약은 ‘약 이름 미설정’ 항목으로 가져옵니다. 프로그램이 꺼져 있던 동안 예약 시각이 지났으면 재실행 시 미확인 알림을 다시 시작합니다.

기존 로보독 연결과 작업 스레드를 공유하므로 추가 Open("COM3") 호출은 하지 않습니다. 현재 리액션과 효과음 대기를 마친 뒤 복약 알림을 시작합니다. 복약 확인 중에는 키오스크 리액션을 거절합니다. 취소된 예약의 대기 명령은 실행하지 않고, 이미 시작한 동작은 마친 뒤 멈춥니다.

AI 연결을 기다리고 QR 모드 응답이 없으면 15초 뒤 다시 시도합니다. 잘못된 QR·문자 해독 오류는 완료로 처리하지 않습니다. 실제 모드는 AI 모듈이 필요합니다. 모의 모드에서는 알림이 울린 뒤 **모의 모드 · STOP QR 확인 시험** 버튼으로 흐름을 확인할 수 있습니다.

QR 이미지는 포함되어 있어 추가 QR 패키지를 설치할 필요가 없습니다. 실제 장치의 음성·모션·AI 카메라 인식은 실물 확인이 필요합니다.

## 소리와 애교

시작 창에서 **로보독 내장 소리 사용**, **무작위 몸 애교 사용**을 켭니다.
로봇에 요청하기 전에 PC 안내를 취소하고 0.15초 기다립니다. 효과음 호출 후 4.5초의 재생 여유가 끝날 때까지 로봇 처리 중 상태를 유지해 다음 효과음과 PC 안내가 겹치지 않도록 합니다. 제공 API에는 사운드 재생 완료를 조회하는 함수가 없어 이 대기 시간을 사용합니다.
실제 장치가 연결된 상태에서 브라우저 하단의 **로봇 소리 시험**, **애교 시험**으로 확인합니다.
모의 모드에서는 이벤트만 기록되고 실제 로봇에서 소리/동작은 나오지 않습니다.

- 소리는 설치된 sound()의 함수 시그니처를 검사해 2인자 또는 3인자 방식으로 호출합니다.
  문서 예시의 멍멍, 안녕, 개소리, 중간 상수만 사용하고 숫자를 추측하지 않습니다.
- 몸 애교는 제조사 내장 인사(GREETING), 앉기(SITDOWN), 기지개(STRETCH), 서기(STANDUP)를 조합한 **15가지 순서** 중 하나를 고릅니다.
  직접 다리 각도·모터·좌우 기울이기·앞뒤 굽히기 코드는 제거했습니다.
  한 반응에 눈 표정 1회 + 몸동작 순서 1개가 실행됩니다. 순서는 1~3개 동작으로 구성됩니다.
  ‘감사’ 표정이 들어간 5개 반응은 소리 겹침 보고에 따라 추가 효과음을 끕니다(sound=None). 나머지 반응은 시작할 때 내장 소리를 1회만 재생합니다. 띠리리는 사용하지 않습니다.
  예: 인사→앉기, 앉기→인사, 기지개→인사, 앉기→서기→기지개, 기지개→서기→앉기, 인사→서기→기지개.
  초롱초롱·ILOVEU 눈에는 멍멍·안녕 소리만 조합하며, 감사 눈에는 추가 효과음을 붙이지 않습니다. 순서 중간에 소리를 다시 재생하지 않습니다.
  소리는 시작 창의 로보독 내장 소리 사용 설정을 따릅니다. 몸동작을 꺼도 눈과 활성화된 소리는 나옵니다.
  눈 표정은 몸동작 후에도 유지합니다. 한 기능이 실패해도 다른 기능은 계속 실행하고 오류를 표시합니다.
  각 동작 뒤 2초씩 기다려 전체 순서는 2~6초입니다. 정상 종료 때 인사·앉기·기지개·서기 중 마지막 자세를 유지합니다.
  전송 오류로 순서가 끊겼을 때만 서기 복귀를 시도합니다.
  설치 라이브러리에 있는 동작으로만 구성된 순서를 사용합니다. 지원되는 순서를 한 번씩 섞어 쓰고 연속 중복을 피하며, 가능하면 시작 동작도 직전과 다르게 고릅니다. 리액션 실행 중이거나 효과음 대기 시간이 남으면 칭찬·완료·애교 시험·소리 시험 요청을 모두 거절합니다. 나중에 실행할 예약도 쌓지 않습니다.
- 안내/도전 모드의 정답은 **화면에 제시된 주문과 일치하는 선택**입니다.
  안내 버전에서는 이용 방식/메뉴/옵션 화면 각각의 조건을 모두 맞췄을 때 한 번만 칭찬 소리와 몸 애교를 요청합니다. 옵션은 전 항목을 맞출 때까지 움직이지 않습니다. 다음·주문 완료 버튼, 재선택·화면 재방문에서는 추가 몸 애교를 요청하지 않습니다.
  스스로 버전에서는 중간에 정답 여부를 알리지 않으며, 맞는 주문을 제출한 뒤에만 완료 애교를 요청합니다.
  안내 버전은 오답을 바로 고치도록 돕습니다. 스스로 버전은 오답도 진행/제출할 수 있고 결과 화면에서 비교한 뒤 수정합니다.
- 소리/제스처 오류는 화면 하단에 구체적으로 표시하고 연결 실패 시 모의 모드로 진행합니다.
- 소리/애교 사용을 껐다면 프로그램 종료 후 시작 창에서 다시 켜세요.

아직 소리가 없으면 **로봇 소리 시험 후 화면의 오류 문구**를 확인하고
Thonny에서 check_environment.py를 실행하세요. Python 실행 파일, 라이브러리 위치,
sound 함수 정의와 필요한 상수의 존재 여부가 출력됩니다. 이 검사는 실제 연결을 열지 않습니다.
명령 호출 성공만으로 실제 기기의 수신/스피커 출력까지 보장할 수 없으므로 장치에서 확인해야 합니다.

PC의 한국어 문장 안내와 로보독의 내장 효과음은 별개입니다.
PC 음성은 브라우저에 설치된 로컬 한국어 음성을 사용합니다. 없거나 실패하면 화면 문구로 안내합니다.
다시 듣기는 도움 횟수를 늘리지 않습니다. 로보독이 한국어 안내 문장을 발화하는 기능은 아닙니다.

## 화면과 학습 규칙

메가커피 참고 사진의 노란 상단 분류 탭, 음료 사진 카드, 주문 목록과 큰 주문 버튼을 반영했습니다.
화면에는 내장 image_gen으로 새로 생성한 음료 8종 이미지를 사용합니다. 파일은 web/assets/generated/에, 생성 프롬프트와 경로는 references/generated-drinks.json에 기록했습니다. 쿠키·머핀 그림은 web/assets에 포함했습니다. 대표 이미지는 실제 제공된 음료와 다를 수 있습니다.
가격은 교육용 가상 가격입니다. 실제 주문·결제·멤버십 수집은 없습니다.
연습을 위해 메뉴/옵션을 단순화했고 한 번에 음료 1잔과 사이드 최대 1개를 주문합니다. 벤티·토핑·사이드 조합은 실제 매장 판매 구성과 다를 수 있습니다.

기본 가이드·힌트 보기·자세한 도움은 다음처럼 구분합니다.

| 도움 종류 | 알려주는 내용 | 화면 표시 |
|---|---|---|
| 안내 방식의 기본 가이드 | 현재 할 일만 한 문장으로 자동 안내 | 위치·영역·정답 버튼 강조 없음 |
| 힌트 보기 | 찾을 카테고리·항목 위치와 개념 단서 | 해당 영역에 점선 표시 |
| 자세한 도움 | 정확한 버튼 이름과 누를 순서를 번호로 안내 | 정답 버튼을 초록색으로 강조 |

안내 버전은 현재 할 일을 짧게 자동으로 읽고 정답 여부를 바로 알려줍니다. 기본 안내에는 조작 위치·개념 설명·정답 버튼 강조를 넣지 않습니다. 스스로 버전은 같은 주문 목표만 보여주고 자동 설명·가이드 패널·선택 영역 표시·중간 정답 피드백을 제공하지 않습니다. 유효한 선택이면 진행하고 제출 후 결과를 확인합니다.
도움 요청은 현재 화면에만 적용하며 다음 화면·뒤로 가기·수정 시 기본 수준으로 돌아갑니다.
힌트를 여러 번 눌러도 자세한 도움으로 자동 상승하지 않습니다. 누른 버튼의 수준을 따릅니다.
다시 듣기는 현재 도움 수준의 안내를 반복하고 도움 횟수를 늘리지 않습니다.
도움을 받아도 안내/스스로 버전 자체는 바뀌지 않습니다.
이전 화면에서는 선택값과 도움 이력을 유지합니다. 메뉴를 바꾸면 온도와 추가 옵션은 초기화됩니다.
주문·목표 주문, 완료 여부, 도움 횟수, 안내 수준, 과제/스테이지 번호를 data/results.jsonl에 로컬 저장합니다.
완료한 스테이지 목록은 안내/스스로 버전별로 나눠 data/progress.json에 저장합니다.
이전 4단계·6단계 과정은 과제 내용이 달라 새 16단계 완료로 계산하지 않습니다. 기존 진도는 다음 저장 시 previousCurriculum에 보존하고 새 과정의 진도는 버전별로 다시 기록합니다.
제출 기록에는 버전, 정답 여부, 실패한 시도 횟수도 포함합니다. 개인 식별 정보는 수집하지 않습니다.

보행·회전·물구나무·직접 다리 굽힘·직접 모터 각도 명령은 호출하지 않습니다. 정상 종료 시 제스처가 끝날 때까지 기다립니다.
Thonny에서 프로세스를 강제 중지하면 정리 절차가 보장되지 않으므로 프로그램의 종료 버튼을 사용하세요.

- kiosk.py: 이전 Tkinter UI 보존본

소리의 두 호출 형식, 15가지 몸동작 순서와 서로 다른 끝자세, 동작별 대기 시간을 확인합니다.
실제 Windows와 로보독의 물리적 소리/동작 반응은 별도 확인이 필요합니다.

이번 수정 검증: 자동 테스트 60개 통과(GUI 건너뜀 0). Chrome에서 16개 전체 주문,
모든 카테고리·옵션·사이드, 랜덤 주문 표시·같은 주문 재도전·새 주문 생성,
안내/스스로 버전과 재수정·도움·별도 진도 및 작은 화면을 확인했습니다.
랜덤 주문 2,000개에서 모든 선택값이 나오고 음료별 온도 제한을 지키는지 검증했습니다.

## 16개 주문 미션

모든 미션은 빈 주문에서 시작해 이용 방식 → 메뉴 → 옵션·사이드 → 주문 확인 → 완료로 진행합니다.
단계 이름만 외우는 대신 음료 종류, 이용 방식, 온도, 옵션 조합과 사이드를 폭넓게 연습합니다.
화면의 연습 주문과 음성 안내는 현재 화면에서 선택할 조건만 알려 줍니다. 전체 주문은 최종 확인 화면에서 표시·안내합니다.

| 단계 | 미션 | 연습 범위 |
|---|---|---|
| 1 | 첫 커피 한 잔 | 기본 주문 전체 흐름 |
| 2 | 커피 말고 딸기 | 카테고리 이동 |
| 3 | 매장에서 따뜻하게 | 매장 이용과 HOT 선택 |
| 4 | 따뜻한 차 한 잔 | 티 카테고리와 온도 구분 |
| 5 | 주스는 크게 | 주스 카테고리와 크기 변경 |
| 6 | 단맛은 조금만 | 당도 낮추기 |
| 7 | 나만의 아샷추 | 베이스 음료와 샷 조합 |
| 8 | 진한 바닐라 커피 | 온도와 샷 수량 구분 |
| 9 | 딸기 위에 휘핑 | 크기와 휘핑크림 조합 |
| 10 | 달지 않은 초코 라떼 | 토핑과 당도·크기 조합 |
| 11 | 차와 버터 쿠키 | 사이드 종류 구분 |
| 12 | 주스와 초코칩 쿠키 | 음료·사이드 주문 확인 |
| 13 | 덜 단 아샷추 세트 | 샷·크기·당도·사이드 조합 |
| 14 | 달콤한 토핑 세트 | 여러 옵션을 빠짐없이 확인 |

### 최고 난이도: 완전 랜덤 실전

- 고정 예시 목록에서 뽑지 않고 음료와 모든 조건을 각각 무작위로 생성합니다.

## 안내 멘트 출력 확인

제공된 RoboDog 공개 API에는 내장 사운드 재생만 있고 임의 문장 TTS나 녹음 파일 전송/재생 API는 확인되지 않았습니다.
작성 환경에도 kocoafab_robodog가 설치되지 않아 추가 기능을 확인할 수 없었습니다.
따라서 현재 버전은 문장 안내를 PC의 한국어 음성으로, 칭찬 효과음과 애교를 로보독으로 분리합니다.
음성 출력 경로는 API 응답의 voice.route와 reactions.py의 guidance_voice_capability에 명시되어 있습니다.
실제 설치 라이브러리에서 추가 문장 재생 기능이 확인되면 그 API에 맞는 로봇 음성 어댑터를 구현해야 합니다.
존재가 확인되지 않은 speak/say 함수는 호출하지 않습니다.

## 안내 버전과 스스로 버전의 차이

| 항목 | 안내 버전 | 스스로 버전 |
|---|---|---|
| 정답 위치 | 자세한 도움에서만 정확한 버튼 강조 | 자세한 도움을 요청한 화면에서만 강조 |
| 문장 안내 | 화면 이동과 선택마다 현재 할 일 자동 안내 | 시작·화면 이동·선택 시 자동 음성 없음. 도움·다시 듣기 요청 시만 안내 |
| 선택 직후 | 맞고 틀림을 바로 알려줌 | 정답 여부를 알려주지 않음 |
| 다음으로 이동 | 정답이어야 이동 | 유효한 선택이면 이동 |
| 제출 | 정답 주문 확인 후 완료 | 오답도 제출, 실제 선택과 목표를 비교 후 수정 가능 |
| 몸 애교 | 화면 조건 전체 충족 시 한 번, 다음·완료 시 추가 동작 없음 | 올바른 주문 제출을 마친 뒤 한 번 |
| 진도 | 안내 버전 별도 저장 | 스스로 버전 별도 저장 |

스스로 버전에서도 힌트와 자세한 도움을 언제든 요청할 수 있습니다.
도움 요청은 기록되며, 다시 듣기는 도움 횟수를 늘리지 않습니다.
다른 주문이 제출됐을 때는 완료 배지가 생기지 않고 ‘다시 수정하기’로 고쳐 제출할 수 있습니다.

몸동작 변경 검증: 가짜 장치에서 15가지 서로 다른 명령 순서, 4가지 끝자세, 각 동작 뒤 2초 대기, 눈 1회·추가 소리 최대 1회(감사 표정은 0회), 오류 시 서기 복귀, 직접 다리·모터·이동 명령 미호출을 확인했습니다. 실제 로보독의 물리적 반응은 실물에서 확인해야 합니다.

화면별 안내: 이용 방식 화면에서는 매장/가져가기만, 메뉴 화면에서는 음료와 카테고리만 안내합니다. 옵션 화면에서는 아직 맞추지 않은 항목을 하나씩 안내합니다. 안내 방식의 기본은 현재 할 일만, 힌트는 찾을 단서와 개념·위치, 자세한 도움은 정확한 선택값과 순서까지 알려 줍니다. 스스로 방식은 요청하기 전까지 가이드 패널과 조작 보조를 숨깁니다. 전체 주문은 최종 확인에서만 읽습니다. 화면 전환 시 이전 음성을 취소하고, 다시 듣기는 현재 화면의 안내를 재생합니다.

도움 수준 검증: 기본·힌트·상세 문구의 차이, 실제 음성에 전달되는 문장, 영역/정답 버튼 강조 차이, 반복 요청·화면 이동 시 초기화와 도움 횟수를 자동 검증했습니다.

힌트 미사용 시 두 방식의 차이도 검증합니다. 동일한 과제에서 안내 방식은 현재 할 일의 자동 음성·즉시 정답 판정을 제공하고, 스스로 방식은 자동 음성/보조 표시/중간 정답 판정 없이 오답도 제출할 수 있는지 확인합니다. 도움을 요청해도 버전은 바뀌지 않습니다.

가이드 모드의 온도 화면 예시: 기본은 “주문에 맞게 온도를 선택해 주세요.”만 말합니다. 힌트는 “HOT은 따뜻하게, ICE는 차갑게”의 뜻을 설명하고 온도 항목을 점선으로 표시합니다. 자세한 도움은 요청에 맞는 정확한 버튼(예: 차갑게)과 조작 순서를 알려주고 해당 버튼을 초록색으로 강조합니다. 기본에는 위치 단서나 버튼 강조가 없습니다.

최근 도움 강화 범위: 스스로 방식과 가이드 방식의 기본 안내는 유지했습니다. 가이드 방식에서 힌트를 누르면 선택의 뜻과 이유·찾을 위치·현재 선택을 함께 설명합니다. 자세한 도움은 현재 상태를 확인하고 정확한 버튼·선택 표시·다음 조작을 번호별 줄로 보여 줍니다. 예를 들어 초코칩 힌트는 음료 토핑과 별도 쿠키를 구분해 설명하며, 자세한 도움은 현재 없음에서 추가로 바꾸는 클릭 순서를 안내합니다. 이 확장은 가이드 방식의 도움 요청에만 적용합니다.

## 미션 가독성과 간결한 화면

미션을 화면 최상단의 고정된 노란 카드에 표시합니다. 현재 미션 본문은 큰 화면 30px, 작은 화면 23px이며 큰 글씨·굵은 테두리·진한 색으로 구분합니다. 음료 이름과 선택 버튼도 키웠습니다. 장식 캐릭터·반복 소개 문구·미션 목록의 중복 설명을 덜어냈고 연결 상태와 시험 기능은 접힌 설정 영역에 모았습니다. 실제 화면 스타일은 web/readable.css입니다.

## 소리 중복 방지

시작·힌트·자세한 도움·다시 듣기는 PC 문장 안내만 사용하고 별도 로봇 효과음을 호출하지 않습니다. 칭찬 때는 눈 표정·몸동작과 로봇 효과음을 한 번 요청하고, PC 안내는 로봇 반응 처리와 효과음 대기 시간이 지난 뒤 재생합니다. 같은 안내의 연속 재생을 억제하며 다시 듣기는 명시적인 재생 요청으로 처리합니다. 화면 변경·음성 끄기·소리 시험 시 이전에 대기 중인 문장을 취소합니다. 로봇 라이브러리에 재생 완료 조회 API가 없어 대기 시간은 4.5초를 기준으로 합니다. 실물 스피커의 출력은 장치에서 확인해야 합니다.

이번 화면·음성 검증: 60개 자동 테스트 통과, Chrome에서 생성 음료 이미지 8종 로딩·16개 주문·가이드 단계 차이·중복 PC 음성 억제·이전 문장 취소·작은 화면 가로 넘침 없음·미션 최소 글씨 크기를 확인했습니다.
